# Vorbereitung des Bau-Auftrags (03.09.2026)

Eric hat an diesem Tag beauftragt, den Bot neu zu bauen: "maximal autonom UND
maximal effizient, drakonischste Strafen fuer Haenger". Das Erzeugnis dieser
Vorbereitung ist der Auftragstext `AUFTRAG-BAU-2026-09.md` (eine Ebene hoeher)
fuer eine frische Fable-5.1-Sitzung im Modus ultracode.

Hier liegt das Material, aus dem er entstand - acht Recherchen mit
Datei:Zeile-Belegen und drei unabhaengige Entwuerfe aus verschiedenen Winkeln.
Die Recherchen sind **die Belegsammlung** zum Auftrag: wer beim Bauen wissen
will, woher eine Zahl kommt, findet sie hier, ohne den Quellcode erneut zu
durchsuchen.

| Datei | Inhalt |
|---|---|
| `R1.md` | Kartierung aller 106 src/-Skripte: Zweck, RAM, bewaehrt/fragil/tot, Kontrakte unter data/, Motor bn4net.js im Detail |
| `R2a.md` | Harte Regeln woertlich (Eric, CLAUDE.md, Memory) und die Fallen mit Datum und Mechanismus |
| `R2b.md` | Befunde des Autonomie-Audits vom 02.09. und die gemessenen Zahlen |
| `R2c.md` | Formeln aus doku/, die Route Eintrag fuer Eintrag |
| `R3.md` | Spielquellcode v3.0.1: isTrusted, Singularity-RAM, Spielstand/IndexedDB, Remote-API, lokale Instanz, Zeitraffer, Exit-Bedingungen, API-Gating je Gewerk |
| `R4.md` | Effizienz je Knoten der Route, fehlende Gewerke mit Aufwand und Ertrag |
| `R5.md` | Haengererkennung: Signale, Uhren, Strafleiter Sprosse fuer Sprosse |
| `R6.md` | Schutzprotokoll fuer den Live-Spielstand: Schadenspfade, Backup, Trennung Live/Test |
| `entwurf-1.md` bis `entwurf-3.md` | Drei unabhaengige Fassungen des Auftrags (Winkel: Prozess, Architektur, Spielstrategie), aus denen die Synthese entstand |

Erzeugt mit einem Workflow aus 14 Agenten (Recherche, Entwurf, Synthese) plus
Skeptiker- und Vollstaendigkeitsrunden. Die Recherchen haben NUR gelesen.
